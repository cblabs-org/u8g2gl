Measured 2026-10-21/22. **Build only; nothing was flashed.** Everything ran through the PlatformIO
MCP (`build_project`, which runs `pio run --environment esp32dev`), on copies of foundation made with
`git archive` into this worktree's `tmp/`. **Nothing was written to `esp32-app-foundation`.**

- **Toolchain:** pioarduino `espressif32` 55.3.311 — arduino-esp32 3.3.11, ESP-IDF 5.5.5,
  `xtensa-esp-elf` gcc 14.2.0. The same platform `device-measurements/EVIDENCE.md` used, so its
  figures are comparable on that axis (F-PLATFORM: an unpinned `espressif32` resolves differently
  on another machine).
- **Runtime copies**, library-only and named `u8g2gl` (F-LINK; F-GLOB):
  - 0.8.0: `git archive 99ac4a3 src include library.json`
  - 0.10.0: `git archive c30cd2d src include library.json`
- **Foundation:** `499142f8` (held integration tip) for the migrated board; `7396e43d` for the
  legacy board, as in `device-measurements/EVIDENCE.md`. The `[u8g2gl]` pin is replaced by a
  `symlink://` to the runtime copy; no other edit.

## C3 — flash and RAM on `esp32dev`

**Method.** Clean `esp32dev` builds of `499142f8`. Every build compared contains
`esp_diagnostics` (`diag_log_add` present in the ELF), because clean builds here vary by about
1.8 KB on that alone (F-DIAG). The delta is attributed with `nm -S` on the two ELFs.

| Build | RAM (B) | Flash (B) | Of 1 572 864 B app partition |
|---|---:|---:|---|
| 0.8.0, clean build 1 | 57 340 | 1 345 159 | 85.5% |
| 0.8.0, clean build 2 | 57 340 | 1 345 143 | 85.5% |
| **0.10.0**, clean build 1 | **57 380** | **1 345 631** | 85.6% |
| 0.10.0, clean build 2 | 57 380 | 1 345 631 | 85.6% |
| 0.10.0, UI regenerated by CLI 0.13.1 | 57 380 | 1 345 631 | 85.6% |
| *Recorded at 0.8.0 on 2026-10-13* | *57 340* | *1 345 115* | *`device-measurements/EVIDENCE.md`* |

**0.8.0 → 0.10.0: RAM +40 B; flash +472 to +488 B (+0.03%). Headroom 227 233 B.** 0.8.0's two
clean builds differ by 16 B and today's differ from 2026-10-13's by 28–44 B, both with
`esp_diagnostics`; the 0.10.0 builds are identical to the byte.

**Attributed** ([evidence/c3-symbol-delta.txt](evidence/c3-symbol-delta.txt)): net +487 B text,
+40 B weak objects (vtables), +16 B data, +25 B bss.

| Where | Bytes | Why |
|---|---:|---|
| Observer removal: `~u8g2gl_obj` +52, `u8g2gl_remove_*observer*` +109, four subjects' `remove_observer` +88 | +249 text | 0.10.0's change to object teardown |
| `u8g2gl_label::tick` +91, `on_size_changed` +18, `set_coords` +34, others | ~+200 text | label and geometry changes |
| `u8g2gl_resume_notify` +28, `s_resume_cb` / `s_resume_user_data` / `s_in_handler` +9 bss | +37 | the PR-5R2 resume callback |
| `s_binding_pool` | **+16 bss** | 4 bindings, each 4 B larger |
| `ui_obj_hostname/wifi/uptime/heap` | **+16 data** | 4 objects, each 4 B larger |
| `vtable for u8g2gl_obj` +36, `u8g2gl_label` +4 | +40 | new virtuals |

**Regenerating with CLI 0.13.1 changes no byte.** The only differences in the generated files are
the generator stamp and the runtime floor (`U8G2GL_REQUIRE_RUNTIME_VERSION(0, 7)` → `(0, 10)`):
F-REGEN is real, but it moves no code.

**Against legacy, for scale.** The same-session builds used for C4 below: legacy `7396e43d`
RAM 57 500 B, flash 1 336 147 B (**84.9%**); migrated at 0.10.0 RAM 57 380 B, flash 1 345 647 B
(**85.6%**). Both contain `esp_diagnostics`. The two foundation commits differ in more than
U8G2GL (the integration branch's own WO-B work), so the +9.5 KB is an upper bound on what the
framework costs, not its attribution.

**What this does not show:** heap at run time with WiFi and TLS active — this is a link-time
measurement of a firmware that contains them; the firmware was not run. Not `esp32s3nano`.

## C4 — the edit–regenerate–rebuild loop

§6's text (`c30cd2d`): *not slower for any reason the framework controls; the generator's own cost
and the compile time are measured separately from the build system's.* This measurement supplies
those three numbers. Whether the build system's share is one "the framework controls" is the
judgement §6 leaves to the gate; it is argued in the dossier, not here.

**Method.**
- **Trees:** legacy `7396e43d`; migrated `499142f8` at runtime 0.10.0 with the pre-build hook
  configured (`custom_u8g2gl_cli` → this worktree's CLI 0.13.1), so every build regenerates.
- **The edit**, identical in kind on both sides: row 3's `y` toggled 30 ↔ 31 — `_row3(4, 30, …)`
  in `DiagnosticsBoard.cpp`, `name="uptime" … y="30"` in `screen_diagnostics.xml`. Each edit
  build recompiled exactly one file (`DiagnosticsBoard.cpp` / `ui_screen_diagnostics.cpp`).
- **Rounds:** five, each `legacy no-change → migrated no-change → edit → legacy edit → migrated
  edit`. Time is PlatformIO's own `Took` line, not MCP task time. Host load 1.3–2.2 during rounds.
- **Warm-up:** the second build of each tree recompiled everything (2 023 / 2 049 files) with no
  input change, then settled; both are discarded and labelled in the data. All timed builds
  compiled 0 files (no-change) or 1 (edit).
- **Generator alone:** `node cli.js generate … --target ssd1322`, five runs, `time -p`.
- Raw data: [evidence/c4-rounds.tsv](evidence/c4-rounds.tsv).

| | Legacy | Migrated | Migrated − legacy (paired median, range) |
|---|---:|---:|---:|
| No-change build (fixed per-build cost) | 18.79 s (18.72–19.07) | 24.30 s (24.23–24.50) | **+5.48 s** (5.21–5.73) |
| Edit build | 22.71 s (22.63–22.73) | 27.61 s (27.45–27.65) | **+4.90 s** (4.74–5.00) |
| Edit − no-change (the work an edit causes) | 3.88 s (3.64–4.01) | 3.17 s (3.15–3.35) | **−0.71 s** |

**The three numbers §6 asks for:**

1. **The generator: 0.04–0.06 s** (five runs: 0.06, 0.04, 0.04, 0.04, 0.04). It runs on every
   build, edit or not, so it sits inside both rows.
2. **Compilation and link of the edit: 0.71 s faster than legacy.** The migrated edit recompiles a
   generated translation unit; the legacy edit recompiles the hand-written board, which is the
   larger file.
3. **Fixed per-build overhead: +5.48 s**, present when nothing is compiled at all. Its components
   are PlatformIO's library dependency finder, the pre-build scripts, and the hook (whose
   generator is 0.05 s of it). The dependency-graph output is 6 265 lines for legacy and 8 944 for
   the migrated tree — the same sizes `device-measurements/EVIDENCE.md` recorded (6 265 / 8 934) —
   and that walk is the only component that grows with the three added libraries (`u8g2gl`,
   `U8G2GLDisplay`, `U8G2GLUI`).

**Not re-measured here:** the split of the +5.48 s between the dependency walk and everything else
was not timed directly. The attribution to the dependency finder rests on 0.8.0's S2 experiment
(`lib_ldf_mode = off` with explicit `lib_deps` took the same tree from +6.24 s *above* legacy to
14 s *below* it), plus the generator's measured 0.05 s. S2 was not repeated at 0.10.0.

**Cross-check against earlier measurements, each on its own basis:**

| Figure | Basis | Runtime / CLI | Source |
|---|---|---|---|
| +4.99 s, generator 0.05–0.07 s, compile faster | MCP task time | 0.7.0 | foundation `pr-u8g2gl-05/evidence/EVIDENCE.md` |
| +6.24 s (no-change S0 − legacy) | wall clock, interleaved | 0.8.0 / 0.12.0 | `device-measurements/EVIDENCE.md` |
| **+4.90 s edit, +5.48 s no-change** | PlatformIO `Took`, interleaved | **0.10.0 / 0.13.1** | this file |

The magnitudes differ by method and host load; the shape is the same in all three: the generator
is negligible, the compile is faster, and the whole regression is fixed per-build overhead.
