## 1. §13.2 — which values must fit `int16_t`? (blocks WO8b/WO9 emission)

§13.2 says the `int16_t` rule covers "any anchor or constant", and then that build-time
arithmetic may use wider intermediate values and only a *result* that does not fit is an
error. Those two readings differ for a constant declared `value="40000"` that is never used
in a coordinate, and for an anchor whose arithmetic exceeds `int16_t` before the final
subtraction.

**WO7b implements:** resolved `x`, `y`, `width`, `height` must fit `int16_t`
(`U8G2GL_COORDINATE_OUT_OF_RANGE`), checked before and separately from the container-bounds
check. Constants keep the `int32_t` check at their declaration.

**Recommendation:** keep it as implemented and tighten §13.2's first sentence to "a resolved
coordinate". A constant is not a coordinate until it is used as one, and a `<const>` shared
by a coordinate and a `set_time()` argument would otherwise be unusable.

**If you rule the other way,** the check moves to constants and anchor intermediates, which
is a small change in WO8a's resolver work.

## 2. §6.6 vs §13.4 — the `wd_` prefix contradicts itself (WO7 S1)

§6.6: "User element tags are unprefixed or carry `wd_` by convention". §13.4 reserves
anything beginning `u8g2gl_`, `ui_` or `wd_`. So the validator rejects a composite named
`wd_card` — the very convention §6.6 recommends. WO7's worker renamed its fixture to `card`;
WO7b's tests avoid `wd_` for the same reason.

**Recommendation:** `wd_` stays reserved for *generated C++ symbols* only, and §6.6 stops
recommending it as an XML tag prefix — or §13.4 drops `wd_` from the reserved set. Either is
a one-line spec change; the code follows §13.4 today. This matters to PR-08's custom
elements, whose examples use `wd_service_list`.

## 3. §11.3 — the clip-window text is now contradicted by verified source (spec fix)

§11.3 still prescribes `setClipWindow(x, y, x+w-1, y+h-1)` and says `u8g2gl_state_saver`
saves the clip window. Both are wrong against pinned U8G2 2.36.18 (`extern/u8g2`):

- `u8g2.h:352/354` document `clip_x1`/`clip_y1` as "(excluded)"; `u8g2_apply_clip_window`
  bounds `user_x1` by `clip_x1`, whose default is `width`; `u8g2_DrawHVLine` returns on
  `x >= user_x1`. The correct call is `(x, y, x+w, y+h)`, which the runtime now makes in
  exactly one function.
- U8G2 has no clip getter, so the saver cannot restore a clip. Its header now says so, and
  clip lifetime is the render wrapper's documented responsibility.

**Recommendation:** correct §11.3 to the exclusive form and to what the saver actually saves
(draw colour and font; not clip, font mode or bitmap mode — U8G2 exposes no getters for
those).

## 4. The WO4c ruling's premise about negative origins (correction, no action needed)

The WO4c ruling stated that on hardware a negative origin wraps, so "an element partly off
the left edge jumps off the right edge". Verified against the pinned source, that does not
hold for most drawing paths: `u8g2_clip_intersection2` (`u8g2_hvline.c:87–99`) handles the
wrapped case deliberately — its comment says a plain `return 0` "will not handle the case
with negative a" — and frames, boxes, XBM and glyphs all reach it. Such elements draw their
visible part.

**The exception is `u8g2_DrawLine`** (`u8g2_line.c:49–52, 78`): no intersection check,
unsigned `dx`/`dy`, per-pixel loop. A wrapped endpoint costs ~65,000 iterations and the wrong
slope. So the runtime now wraps draw positions explicitly everywhere **except** lines and
outline triangles, which clip to the display in signed arithmetic first.

The ruling's instructions — explicit conversions, clip clamped at both corners — stand and are
implemented. Recorded because two successive PA rulings on this were each right for most
primitives and wrong for one; the lesson is that the rule belongs to the *drawing path*, not
to "U8G2" as a whole.

## 5. `$prop` inside longer text — spec is silent (WO7 F9)

`text="Hi $who"` is not substituted today; only a whole-attribute `$name` is. WO7b makes the
interpolated case a hard error (`U8G2GL_UNSUBSTITUTED_PROP`) rather than letting `$who` reach
generated output literally.

**Recommendation:** ratify the error for schema 0.4 and record interpolation as a candidate
for the next schema bump (it is additive). If you would rather it substituted, it is a small
change in WO8a — but it makes every `$` in text meaningful, which is schema surface.
