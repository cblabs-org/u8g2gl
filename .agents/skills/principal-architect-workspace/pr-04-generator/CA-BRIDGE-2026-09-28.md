## 1. 522 of U8G2's fonts cannot be named at all (§13.4 versus §14.1)

WO11b derived the valid `<builtin>` font names from the pinned submodule: 2039 names, cross-checked
between `u8g2.h` and `u8g2_fonts.c`. **522 of them contain capitals** — `u8g2_font_helvR08_tr`,
`u8g2_font_ncenB12_tr` — and §13.4 requires a name matching `[a-z][a-z0-9_]*`, because the name
doubles as the generated identifier (`ui_font_<name>`). So a `<builtin>` naming any of those 522 is
refused, and a quarter of U8G2's fonts, including the Helvetica and Century Schoolbook families, are
unreachable.

**PA recommendation:** a `<builtin>`'s `name` is a *U8G2 symbol*, not an author-chosen name, so it
should be validated against the derived list and not against §13.4's identifier rule, with the
generated alias taking a mangled form. That keeps identifiers legal without forbidding real fonts.
Alternatively `<builtin>` gains an explicit local name. Either way this is a §13.4 amendment.

## 2. U8G2's 191 legacy `u8g_font_*` macros are refused

They would compile, being macros in U8G2's headers, but they are not in the derived list.
**PA recommendation:** keep refusing them, and say so in the message, because they are U8G2 1.x
compatibility aliases. Confirm, since it is a deliberate narrowing.

## 3. Bound draw-call arguments wrap where object bindings clamp

An object's `bind_x` clamps the subject's value into int16_t (and now adds the container origin
before clamping). A bound argument in a *draw call* is emitted as an expression and reaches a
narrower parameter, where it wraps. So the same XML behaves differently depending on whether §13.5
realised the element as an object — a distinction the author never made.

**PA recommendation:** one semantic for both, and clamping is the one already specified for objects.
This is a runtime and emission change, so it wants a ruling before anyone implements it.

## 4. `style_*` is accepted for any property with a setter

§10 lists nine style properties. The validator accepts `style_<anything>` that names a property with
a setter, so `style_text="x"` builds. WO11b left emission's rule alone rather than choose.
**PA recommendation:** restrict inline `style_*` overrides to §10's nine, because `style_` means
"this is styling" to a reader, and a general per-element override is a different feature.

## 5. A radius still reaches U8G2 unguarded at run time

WO11b checks a rounded box's radius against its own size where both are literal
(`2*(r+1) <= w`, derived from `u8g2_box.c:98–106` and `u8g2_circle.c:52`). Where the size is **bound**,
or a radius arrives through a style, the value only exists at run time and U8G2 receives it
unchecked; below `2r` its internal `w - r - r` wraps in `u8g2_uint_t`.
**PA recommendation:** the runtime clamps the radius to the current size at draw time, which pairs
with item 3's ruling. PR-04 did not do it — it is a runtime change and the box was the validator's.

## 6. §13.1 and §13.7 do not describe the editor target

WO11 delivered editor-target generation: a registry unit, a scene-description JSON (now at format
version 2, carrying the bound origin), and `generate --target-kind firmware|editor`, with output in
`<output dir>_editor` by default and a parity test that renders both targets and compares the draw
calls call for call. §13.1 names two targets but §13.7's file list and the `--json` contract do not
mention any of it. **Spec edits are yours;** the PA has not touched these sections.

## 7. Layering: `validator/` and `generator/` are now mutually dependent (an observation)

WO8c accepted the validator importing `generator/realise/` for the realisation rule. WO11b extended
that: the validator imports shared lookup tables from `generator/emit/` (style properties, colour
values), while `generator/generate.ts` and `check-project.ts` import back from `validator/`. No
import cycle, and every alternative the PA can see means a second copy of a table that [D-17] says
must be data — but the standards do not say where a shared lookup table lives. The readability
review raised it as a judgement call rather than a defect.
