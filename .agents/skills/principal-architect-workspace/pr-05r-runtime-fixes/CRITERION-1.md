# Gate criterion 1, re-measured after PR-05R

Criterion 1 is pixel identity between foundation's legacy `DiagnosticsBoard` and the same screen
migrated to U8G2GL. PR-05 passed it with 0 differing pixels, but with foundation's legacy module
setting `setFontPosTop()` before U8G2GL drew anything. The cut-over deletes that module. This
document records the measurement with the framework establishing that state itself.

## Method

- **What was compiled.** Foundation's render harness, taken with `git archive` of the held
  integration tip (`499142f8`) into `tmp/fdn/` of this worktree, built as-is: no source in it was
  edited. It builds the legacy `DiagnosticsBoard` and the migrated `DiagnosticsScreenBoard` into one
  host binary (`render_harness`) against real U8G2 2.36.18.
- **Which U8G2GL.** This branch's `src/` and `include/` at the commit that bumps the versions to
  runtime 0.8.0 / CLI 0.12.0 (WO5), on top of WO1..WO4: the framework establishes position top,
  direction 0 and reference height all inside its render guard and restores the caller's state. The
  harness takes it through `-DU8G2GL_SOURCE_DIR=<this worktree>`; the configured cache also has
  `-DU8G2_SOURCE_DIR=<this worktree>/extern/u8g2` and `-DRENDER_AFTER_DIR=<this worktree>/tmp/fdn/after-05r`.
  The `u8g2gl_runtime` objects in the harness build are compiled from this worktree's `src/`
  (confirmed from the object paths), and were rebuilt after the version edit.
- **The generated UI** is foundation's committed `uidesign/ssd1322-256x64/u8g2gl/generated`, not
  regenerated by the CLI under test.
- **Display state for the five scenarios (the "normal" frame).** The legacy begin state:
  `begin()`, `setDrawColor(1)`, `setFontMode(1)`, `setFontRefHeightAll()`, `setFontPosTop()`,
  `setContrast(0)`, `setFlipMode(0)`. Baselines are foundation's current legacy renders in
  `tmp/fdn/test/render/baseline/diagnostics_board`.
- **State probe.** The same `connected` scenario drawn under display states that lack one legacy
  call, compared with the normal migrated frame. `plain_user_ui_handler` is `begin()` only (no draw
  colour, font mode, reference height or position), drawn by the generated `ui_handler()` with no
  foundation module involved: this is what a U8G2GL user who has never heard of foundation does.
- **Foundation was not written to.** Everything lives under `tmp/` of this worktree (git-ignored).
- **Re-run:** `cmake --build tmp/fdn/build --target after`.

## Does the PR-05 result hold for U8G2GL alone?

Yes, on the host. Drawn by `ui_handler()` over a display that has had only `begin()` called, with no
foundation module and none of the legacy begin-time calls, the screen is pixel-identical to the
legacy render: 0 differing pixels, in both directions. The legacy module's `setFontPosTop()` and
`setFontRefHeightAll()` are no longer carrying the result; the framework establishes them and puts
the caller's back.

PR-05R's finding was real and larger than the one PR-05 recorded: removing the legacy module
alone cost 1407 pixels (position) and, once that was fixed, a further 274 (reference height).

## What this does not show

- **The device.** This is the host harness against real U8G2, with the display driver stubbed
  (`u8x8_byte_empty`). It does not exercise the SSD1322 panel, the I2C/SPI path, timing or the
  firmware build. An on-device check is a later interactive step, when the owner attaches hardware.
- **The cut-over itself.** The legacy module is not removed in this harness; the probe removes the
  state it carried, not the module's other behaviour.
- **Other screens.** One screen (the diagnostics board) in five input states.
- The harness's pinned U8G2GL SHA (`82ec83f2`) is overridden by `-DU8G2GL_SOURCE_DIR`; the
  measurement is of this tip, not of that SHA.

## On the device — 2026-10-12

**Hardware:** foundation's ESP32-S3 Nano (`arduino_nano_esp32`, USB 303A:1001) with its SSD1322
256x64 (`hardware/esp32s3nano/board.h`: CS 10, DC 9, SCK 48, MOSI 38, no reset pin).

**Firmware:** a scratch sketch (`tmp/device/`, not committed), one `main.cpp`, two runtimes. It
draws foundation's committed generated `diagnostics` screen with the `connected` scenario's exact
row strings, as **a plain user**: `SPI.begin(48, 47, 38, -1)` and `begin()`, and no other U8G2
call before the first frame. It hashes the 2048-byte buffer (mbedTLS SHA-256) after
`clearBuffer()` + render and before `sendBuffer()`, as the harness does, and prints the result over
USB CDC.

**Expected** (host harness against this branch, `connected.bin`): 2048 B, lit **1405**, sha256
