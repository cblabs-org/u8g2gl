## 3. Expressiveness Assessment Summary

### Expressible Statically in Schema 0.4
- **Drawing Primitives**: Box outlines (`<u8g2gl_box filled="false">`), lines (`<u8g2gl_line>`).
- **Single-value Text**: Platform header label (`"Plat"`), bound platform number (`"9"`).
- **Time Representation**: System clock (`<u8g2gl_clock format="hh_mm_ss">`) bound to `system_time`.
- **Static Fallback**: Fallback text (`"No services found."`) with `hidden="true"`.

### Expressible Only via Hand-Expanded Workarounds
- **Service List Columns (`row0Widget`)**: Hand-expanded 3 individual `<u8g2gl_label>` elements (`row0_time`, `row0_dest`, `row0_status`) with fixed pixel coordinates and individual bound subjects.
- **Message Ticker (`msgWidget`)**: Expressed as a single `<u8g2gl_label long_mode="scroll_circular">` bound to a single pre-sanitized string. Multiple message cycling cannot be declared statically.
- **Train Formation Diagram (`formationWidget`)**: Hand-expanded 12 distinct `<u8g2gl_box>` frame outlines and 12 `<u8g2gl_label>` carriage numbers.
- **Secondary Departures (`servicesWidget`)**: Hand-expanded Service 2 as an active 4-column row at `y=54`, with Services 3 and 4 declared with `hidden="true"` as alternate carousel slots.

### Unexpressible in Schema 0.4 (Requires Custom Runtime C++)
- **Dynamic Collection Iteration**: Variable train carriage count (e.g. 4 vs 8 vs 12 coaches) and variable service row count (`[Q-8]`).
- **Per-Carriage Facility Icons & Load Gauges**: Wheelchair/bike icons and proportional passenger occupancy fill bars within each carriage cell (`[Q-15]`).
- **Dynamic Multi-Message Pool Carousel**: Automatic cycling across multiple messages in an array (`[Q-15]`).
- **HTML Sanitization**: Stripping HTML anchor tags present in live National Rail API message feeds.

## 4. Upstream Issue Surfacing (For Principal Architect Triage)

During Wasm harness verification, an upstream discrepancy was discovered between the CLI code generator and the C++ Wasm bridge:

- **Location**: `wasm/bridge.cpp:708` vs `cli/src/core/generator/emit/scene.ts:277`
- **Description**:
  In `wasm/bridge.cpp:708`, the element dispatcher checks:
  ```cpp
  else if (realisation == "draw") {
      if (!render_draw_call(s_display, element)) { ... }
  }
  ```
  However, the CLI generator (`cli/src/core/generator/emit/scene.ts:277`) emits:
  ```typescript
  "realisation": "draw_calls"
  ```
- **Impact**: Any scene JSON produced directly by the CLI generator containing drawing primitives (such as `u8g2gl_box` or `u8g2gl_line`) has its draw calls silently ignored by the Wasm bridge unless `"realisation": "draw"` is matched.
- **Action**: Recorded here for Principal Architect triage outside the worker boundary box.
